# Demo walkthrough

1. Open the landing, enter demo code `246810` and select **Enter workspace**. No email is required. The existing baseline records are labelled synthetic, not claims of real student learning.
2. Create a practice cycle for adding unlike fractions, with a future closing date and a 12–15 minute budget. Paste a short lesson note or upload text/Markdown/a text-layer PDF; confirm the concepts before preparation.
3. Wait for the persisted preparation job. Compare at least two learner paths: a prior supported error and missing evidence should not receive identical explanations. The latter starts with a check.
4. Review actual exercises and branches. Exclude a learner or edit a path; note that the version changes. Approve the current version and publish it.
5. Switch explicitly to a synthetic learner. Request a hint, save an answer and see the saved confirmation. An incorrect check can reveal only remediation already included in the teacher-approved batch.
6. Return to the teacher. Open the lesson brief and supporting attempts. Participation, pending review and delivery are distinct states. Review a short explanation and retain its revision history.
7. Inspect delivery state independently. Mailpit acceptance is not a claim of delivery to a real person. No real waiting period or live model invocation should be implied by the local deterministic mode.

For a live-agent demonstration, configure Bedrock, select `TIZA_AGENT_MODE=bedrock`, and repeat preparation. Only that mode invokes Strands/model tools. Real provider validation requires deployment credentials and is distinct from the offline automated suite.

Optional nema interoperability is complementary: request scoped consent, accept an assertion from the learner's vault, and explicitly export an actual receipt with a new Tiza signing key. Do not promise automatic curriculum alignment or a full-vault sync.
