# Interoperability

The compatibility format stays `nema1.<payload>.<signature>` and `nema/0.1`. Python converts DER ECDSA signatures to raw `r || s` and verifies the original UTF-8 JSON bytes. Keys are Tiza deployment configuration. The Python adapter rejects additional disclosure fields and ambiguous JSON at the Tiza trust boundary.

Readiness has its own authenticated, expiring request and grant. It does not copy a vault ledger or grant access to a browser. Receipt export retains the evaluator and assistance conditions. A teacher cannot export for a learner. Registration and concept alignment remain explicit compatibility steps; a mathematically valid Tiza fraction curriculum is not automatically a nema-recognized catalog.

The protocol fixture contains one NUL byte in a string key separator; this is intentional.
