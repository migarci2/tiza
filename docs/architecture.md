# Architecture and execution

React/TypeScript/Vite communicates only with FastAPI. TanStack Query manages server state. The backend stores classroom membership, immutable assignment versions, approvals, attempts, evidence revisions, deliveries and jobs using SQLAlchemy. PostgreSQL is the deployment database; SQLite is the explicit local-demo substitute. Alembic owns schema migrations.

Supabase Auth verifies email codes server-side. FastAPI issues opaque random HttpOnly session cookies stored as hashes. Writes require an independent CSRF token. Identity and organization come from the session; learner access additionally requires the learner's assignment and enrollment. Production requires secure cookies. Supabase Storage holds private materials; the local demo uses a private filesystem directory.

Preparation creates a job and outbox event in the API transaction. The outbox dispatcher publishes work identifiers; workers claim persisted jobs atomically and validate current organization, teacher permissions and cycle version. Three attempts are allowed; exceptions are recorded by class, without model prompts or personal answers. Redis can be discarded without losing intent. Expired running-job leases return to the queue. One beat and a worker concurrency of one are intentional MVP limits.

The pinned nema estimator derives state and applies its fractional implicit-repetition rule before planning. Tiza then applies a separate deterministic policy that selects reviewed exercise versions, preserves prerequisites and initial checks, and enforces the practice budget. A Bedrock-backed Strands agent receives only its scoped cycle, limited material excerpts and selected candidates. Four tools read context/candidates, save bounded explanations and request human review. It cannot approve, publish, submit learner answers, execute SQL or write mastery. Runs are limited to 12 model calls with bounded output; run metadata stores model, tool names and usage, not private reasoning. The offline demo executes the same policy and writes but explicitly records `model_invoked=false`.

Approval records the exact version, content hash and recipients. Editing creates a future version and cannot change completed attempts. Publication rechecks authorization. Objective answers are graded on the server; requesting a hint is persisted before revealing it. Short explanations remain pending until teacher review. Evidence revisions supersede prior effects while keeping history. Derived state is recomputed from current evidence, not accepted as a permanent label on a person.

An email row is not evidence of learning. The transport persists intent before network I/O, keeps an idempotency key, and marks only `provider_accepted` upon acceptance. Resend reconciliation can establish delivered/bounced/failed states. A send whose result is uncertain beyond the safe retry window is not blindly repeated. SMTP has no equivalent deduplication guarantee and is conservatively escalated as uncertain. Reminder scheduling checks authorization, cancellation, closure, participation and local quiet hours again at execution.

The nema adapter verifies original JSON bytes with P-256/SHA-256 raw signatures. Limited readiness grants are bound to the authenticated learner, exact request, purpose, scope, vault key and expiry. They are external planning hints and never fabricated attempts. Export of an actual verified attempt requires the learner's own action and a configured new Tiza issuer key.

Deployment services are gateway, API, worker, beat and Redis; Mailpit is a demo profile. Caddy serves the SPA and proxies `/api`. Public deployment needs HTTPS, a managed PostgreSQL backup policy and a restoration rehearsal. This single-instance deployment does not claim high availability.
